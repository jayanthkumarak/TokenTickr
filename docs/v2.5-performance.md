# TokenTickr v2.5: Performance Optimization

## Overview
Version 2.5 introduces significant performance improvements focused on reducing Time to Interactive (TTI) and initial bundle size. By moving data layer operations to build-time and implementing aggressive code splitting, we have achieved a faster, more efficient application.

## Key Changes

### 1. Static Data Generation
We moved the OpenRouter model data fetching from runtime (client-side) to build time.
- **New Script**: `scripts/generate-openrouter-static-data.mjs` fetches, filters, and minifies data from OpenRouter API.
- **Output**: Generates `src/lib/openrouter-static-data.ts` (~280KB) containing 350+ models.
- **Benefit**: Eliminates the initial network request to OpenRouter API (often 800ms+), removing a major bottleneck.

### 2. Lazy Loading (Code Splitting)
We optimized the initial JavaScript bundle by splitting heavy components using `next/dynamic`.
- **`ModelSelector`**: Only loads when the "Add Model" modal is opened.
- **`PriceComparisonSection`**: Only loads when needed (off-screen initially).
- **Static Data**: The large static data file is dynamically imported only when needed, preventing it from bloating the main entry bundle.

## Maintenance Guide

### Updating Model Data
Since model data is now static, it does not update automatically on page load. To refresh the data:

1. Run the generation script:
   ```bash
   npm run generate:static-data
   ```
   This will fetch fresh data from OpenRouter and Artificial Analysis, and update the static files in `src/lib/`.

2. Rebuild the application:
   ```bash
   npm run build
   ```

3. Deploy the new build.

### Verification
You can verify the optimizations by checking the Network tab in browser DevTools:
- Ensure no calls to `https://openrouter.ai/api/v1/models` occur on page load.
- Observe separate JS chunks loading when interacting with the "Add Model" button.
